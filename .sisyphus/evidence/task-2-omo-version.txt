BUG (proven empirically in prior round, not re-tested here): the shebang-rewrite
for-loop used an && chain whose last predicate (grep -q "env node") is FALSE for
any file whose shebang isn't node. The loop's exit status is the LAST body
evaluation — with the bin whose shebang doesn't match as the last glob entry,

continue-pattern keeps non-matches at rc=0 while real sed failures still fail.

BEFORE:
    for f in /root/.bun/bin/*; do [ -f "$f" ] && head -1 "$f" 2>/dev/null | grep -q "env node" && sed --follow-symlinks -i "1s|.*|#!/usr/bin/env bun|" "$f"; done
